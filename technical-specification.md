## 2. Цели и задачи

### 2.1 Цель проекта
Разработка веб-приложения для асинхронного взаимодействия пользователей с различными LLM-провайдерами через единый интерфейс с возможностью гибкой настройки обработки сообщений.

### 2.2 Задачи
- [ ] Разработать frontend-приложение на Next.js с интерфейсом чата
- [ ] Реализовать backend API на FastAPI для обработки запросов
- [ ] Интегрировать DeepSeek API как основного LLM-провайдера
- [ ] Реализовать систему middleware для обработки сообщений
- [ ] Создать механизм выбора и переключения LLM-провайдеров
- [ ] Контейнеризировать приложение с помощью Docker
- [ ] Обеспечить асинхронную потоковую передачу ответов (streaming)

## 3. Требования к системе

### 3.1 Функциональные требования
| № | Требование | Приоритет |
|---|------------|-----------|
| 1 | Отправка сообщений в чат и получение ответов от LLM | Высокий |
| 2 | Потоковая передача ответов (streaming) в реальном времени | Высокий |
| 3 | Выбор LLM-провайдера из списка доступных | Высокий |
| 4 | Сохранение истории диалогов | Средний |
| 5 | Настройка параметров генерации (temperature, max_tokens) | Средний |
| 6 | Система middleware для пре/пост-обработки сообщений | Высокий |
| 7 | Управление контекстом диалога | Средний |
| 8 | Экспорт истории чата | Низкий |

### 3.2 Нефункциональные требования
- **Производительность:** Время ответа API < 200ms (без учёта времени генерации LLM), поддержка streaming-ответов
- **Безопасность:** Хранение API-ключей в переменных окружения, валидация входных данных, защита от инъекций
- **Масштабируемость:** Горизонтальное масштабирование через Docker-контейнеры
- **Доступность:** Graceful degradation при недоступности LLM-провайдера

## 4. Архитектура системы

### 4.1 Общая архитектура
```
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│                 │     │                 │     │                 │
│  Next.js App    │────▶│  FastAPI        │────▶│  LLM Providers  │
│  (Frontend)     │     │  (Backend)      │     │  (DeepSeek,etc) │
│                 │◀────│                 │◀────│                 │
└─────────────────┘     └─────────────────┘     └─────────────────┘
                              │
                              ▼
                        ┌─────────────────┐
                        │   Middleware    │
                        │   Pipeline      │
                        └─────────────────┘
```

**Описание:**
- **Frontend (Next.js):** SPA с интерфейсом чата, управление состоянием, SSE/WebSocket для streaming
- **Backend (FastAPI):** REST API, асинхронная обработка запросов, маршрутизация к провайдерам
- **Middleware Pipeline:** Цепочка обработчиков для модификации входящих/исходящих сообщений
- **LLM Providers:** Абстракция над различными API (DeepSeek, OpenAI, Anthropic и др.)

### 4.2 Технологический стек
- **Frontend:** Next.js 14+, TypeScript, Tailwind CSS, Zod
- **Backend:** Python 3.11+, FastAPI, Pydantic, httpx/aiohttp
- **База данных:** PostgreSQL (история чатов), Redis (кэширование, сессии)
- **Инфраструктура:** Docker, Docker Compose

## 6. Описание функционала

### 6.1 Модуль чата (Frontend)
**Описание:** Основной интерфейс взаимодействия пользователя с LLM

**Функции:**
- Поле ввода сообщения с поддержкой многострочного текста
- Отображение истории сообщений с разделением на пользователя и ассистента
- Индикатор загрузки и streaming-вывод ответа
- Кнопки управления: новый чат, очистка, экспорт
- Селектор выбора LLM-провайдера
- Настройки параметров генерации

### 6.2 Модуль API (Backend)
**Описание:** Обработка запросов и взаимодействие с LLM-провайдерами

**Функции:**
- Приём сообщений от frontend
- Маршрутизация к выбранному LLM-провайдеру
- Streaming-ответы через SSE (Server-Sent Events)
- Управление контекстом и историей диалога
- Обработка ошибок и retry-логика

### 6.3 Модуль Middleware
**Описание:** Конвейер обработки сообщений до и после LLM

**Функции:**
- **Pre-processing middleware:**
  - Фильтрация нежелательного контента
  - Добавление системных промптов
  - Модификация параметров запроса
  - Логирование входящих сообщений
- **Post-processing middleware:**
  - Форматирование ответа
  - Фильтрация выходных данных
  - Добавление метаданных
  - Логирование ответов

### 6.4 Модуль провайдеров
**Описание:** Абстракция для работы с различными LLM API

**Функции:**
- Единый интерфейс для всех провайдеров
- Поддержка DeepSeek API (основной)
- Расширяемость для добавления новых провайдеров (OpenAI, Anthropic, etc.)
- Управление API-ключами и лимитами

### 7.3 Коды ответов API

| Код | Описание |
|-----|----------|
| 200 | Успешный запрос |
| 201 | Ресурс создан |
| 204 | Успешно, нет контента |
| 400 | Некорректный запрос |
| 401 | Не авторизован |
| 403 | Доступ запрещён |
| 404 | Ресурс не найден |
| 422 | Ошибка валидации |
| 429 | Превышен лимит запросов |
| 500 | Внутренняя ошибка сервера |
| 503 | Сервис недоступен (LLM провайдер) |

### 7.4 Формат ошибок

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Human-readable error message",
    "details": [
      {
        "field": "temperature",
        "message": "Must be between 0 and 2"
      }
    ],
    "request_id": "uuid"
  }
}
```

### 7.5 Аутентификация

- **Тип:** JWT (JSON Web Token)
- **Access Token:** короткоживущий (15 минут)
- **Refresh Token:** долгоживущий (7 дней)
- **Передача:** Header `Authorization: Bearer <token>`
